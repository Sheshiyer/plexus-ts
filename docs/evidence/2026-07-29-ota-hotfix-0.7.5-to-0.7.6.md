# Plexus OTA Hotfix — v0.7.5 → v0.7.6

Status: clean local release gates complete; protected PR and signed publication pending.

## Why this patch exists

The signed `v0.7.4` → `v0.7.5` OTA canary completed its consent, download,
install, relaunch, version, login, workspace, and local-state checks. The
restarted v0.7.5 app then truthfully reported Clio `GATEWAY OFFLINE` with
`PLEXUS_OMNIROUTE_RELAY_ORIGIN is required.`

The repository variable was available to CI packaging and smoke processes, but
it was never persisted into the installed application. A normal Finder or OTA
launch cannot inherit that CI process environment. The defect is therefore at
the packaged main-process configuration boundary, not in Cloudflare Access,
the Thoughtseed workspace, the EC2 relay, or OmniRoute.

## Correction

- Production main-process code contains one canonical relay authority:
  `https://clio-relay.thoughtseed.space`.
- A packaged launch succeeds with no
  `PLEXUS_OMNIROUTE_RELAY_ORIGIN` process variable.
- If that variable is supplied to a packaged process, it must exactly match the
  baked authority; alternate canonical HTTPS origins fail closed.
- Development retains only the explicit loopback
  `PLEXUS_OMNIROUTE_RELAY_DEV_ORIGIN` override.
- `fetchOmniRouteWithAccess` receives relay authority from its caller and no
  longer reads it independently from process environment.
- The packaged main-process smoke resolves the authority from `app.asar` with
  an empty environment input.

No relay credential, Access assertion, provider key, signing secret, or R2
credential is embedded by this patch.
