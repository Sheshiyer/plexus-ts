# Plexus OTA Hotfix — v0.7.6 → v0.7.7

Status: live carrier diagnosis, complete deterministic verification, and the
clean unsigned package gate passed; protected PR, signed publication, and
installed upgrade proof pending.

## Why this patch exists

The signed `v0.7.5` → `v0.7.6` OTA completed both consent boundaries, download,
install, relaunch, version verification, and account/workspace continuity.
Version `0.7.6` also fixed the packaged relay-origin defect: Clio advanced from
`gateway_offline` to the next truthful boundary, `sign_in_required`.

The Access login flow captured and encrypted a valid Plexus Access JWT in
`tf.accessJwtEnc`. The Clio relay request then sent that token as
`Cf-Access-Jwt-Assertion`. That header is origin-facing: Cloudflare adds it
after Access verification. It is not the client carrier for a request arriving
at the Access edge.

## Live diagnosis

An AWS SSM probe on the production Hermes runner read the existing short-lived
smoke credential without printing it and requested the same protected
`/v1/models` route through three carriers:

```text
Cf-Access-Jwt-Assertion -> 302
CF_Authorization cookie -> 200
Cf-Access-Token         -> 200
```

The relay journal had no corresponding failed request, confirming that the
`302` was produced at the Cloudflare Access edge before the relay. This rules
out the stored identity, Hermes relay, OmniRoute, provider routing, and
Temperance lane policy as the cause.

## Correction

- The main-process relay fetch deletes caller-supplied `Authorization`,
  `Cookie`, `Cf-Access-Jwt-Assertion`, and `Cf-Access-Token` headers.
- It attaches the safe-storage-owned assertion as `Cf-Access-Token`.
- The relay origin remains exactly `https://clio-relay.thoughtseed.space`.
- Only `GET /v1/models` and `POST /v1/chat/completions` remain allowed.
- Redirects remain blocked, so the assertion cannot follow an Access login
  redirect to another origin.
- Error redaction now covers both Access header names.

No relay credential, Access assertion, provider key, signing secret, or R2
credential is embedded by this patch.
