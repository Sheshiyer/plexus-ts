# Plexus v0.7.11 Vault Authority Hardening Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Ship v0.7.11 only after local founder-vault enrichment is strictly bounded by authenticated Worker mappings and cannot expand an employee's project visibility.

**Architecture:** The Worker/D1 remains the only project and assignment authority. Plexus may read a locally Git-synced founder-vault checkout only as an admin-only, allowlisted enrichment source; every vault brief is parsed strictly, joined by exact canonical slug to the Worker snapshot, and reported as diagnostics when malformed, unknown, stale, or unassigned. No runtime GitHub fetch, R2 vault sync, or arbitrary SQLite project creation is introduced.

**Tech Stack:** Electron 43, TypeScript, React 18, Vitest, SQLite cache, Cloudflare Access-backed Workspace Worker, GitHub Actions, Cloudflare R2 OTA feed.

---

## Frozen contracts

- `project_id` and assignment scope come only from authenticated `/v1/project-mappings`; vault data never creates or renames projects.
- A valid vault root is an explicitly selected, local Git worktree with the expected private vault remote and `50-team/`, `60-client-ecosystem/`, and `.obsidian/` markers. The remote URL is not exposed to the renderer.
- The picker, scan, and import actions are admin-only; an employee cannot inspect source paths or candidate metadata.
- Only YAML frontmatter in `60-client-ecosystem/**/project-brief.md` is parsed. `source_of_truth: vault` and an explicit allowed status are required. Invalid/duplicate/unknown briefs are diagnostics, not writes.
- Vault enrichment never modifies worker-owned project identity, assignment, repository verification, time/KPI live values, or update-feed authority.
- R2 remains OTA-only in Plexus; private Git remains vault transport only.

## Dependency rationale and dispatch

T-001–018 freeze contracts before any parallel writer. T-019–028 depend on the mapping snapshot. T-029–038 consume stable types/IPC and run after contract merge. T-039–054 can run in two non-overlapping worktrees after the code contract is frozen. T-055–070 are serialized protected-release work.

Use `te-dispatch-paid` only for independent waves, with one worktree per task. Do not run concurrent workers touching `src/shared/types.ts`, `package.json`, lockfiles, workflows, `src/main/main.ts`, or `ProjectManager.tsx`. Each worker must return changed files, focused-test evidence, no contract drift, and a handoff note.

## Verification strategy

- Security: employee IPC denial, no renderer filesystem/remotes, strict frontmatter, provenance validation, exact Worker slug/assignment join, no vault-created identities.
- Reliability: bounded async scanning, partial-error diagnostics, cancellation behavior, offline/Worker-unavailable fail-closed behavior.
- UX: admin-only controls, truthful mapped/blocked states, safe recovery copy.
- Release: clean full gate, protected three-platform CI, tag ancestry, Candidate, protected Publish OTA, public hash/cache verification, and installed `0.7.10 → 0.7.11` continuity proof.
